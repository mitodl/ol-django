### Added

- `MITOL_APIGATEWAY_ADOPT_UNLINKED_USER_BY` lets the backend adopt a pre-gateway account that has no lookup-field value yet, matching it on a second field (typically `email`), instead of creating a duplicate on its owner's first login through the gateway. "No value yet" covers both an empty string and NULL, since apps differ on which they store. Defaults to `None` (off).

### Fixed

- `ApisixRemoteUserBackend.lookup_field` now reads `MITOL_APIGATEWAY_USER_LOOKUP_FIELD` instead of hardcoding `global_id`. The setting shipped but was never read.
- `ApisixUserMiddleware.process_request` compares the already-authenticated user on the gateway lookup field rather than `USERNAME_FIELD`. Where an app's `USERNAME_FIELD` is not the lookup field, `RemoteUserMiddleware`'s own comparison never matched, so every request logged the session out and re-authenticated.
- `configure_user` writes the user row (and any `additional_models` row) only when a mapped value actually differs from what is stored. It ran on every authenticated request and saved unconditionally.
- An ambiguous remote identity is now refused explicitly, with a log line naming the lookup field and value, rather than surfacing as a generic "Unable to authenticate api gateway user".
- A mapped name that is not a concrete model field no longer breaks the save. This was masked before by the unconditional `user.save()`.
